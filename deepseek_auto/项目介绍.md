# deepseek_auto 项目介绍

DeepSeek Android App 全自动化 RPA Worker：自动登录换号、破解人机验证、接收后台问答任务、采集 AI 回答（含深度思考过程）并回传结果。与 doubao_auto 同构，平台标识为 `deepseek_app`。

---

## 一、它能做什么

1. **全自动登录流程**（对应标注图 ①~⑩）
   - 登出：① 点开左侧抽屉 → ② 点抽屉右下角「三个点」→ ③ 设置页划到底点「退出登录」→ ④ 弹窗确认
   - 登录：⑤ 点「手机验证码登录」→ ⑥ 协议弹窗点「同意」→ ⑦ 输手机号 → ⑧ 点「发送验证码」→ ⑨ 填验证码 → ⑩ 点「登录」
2. **人机验证自动破解**（项目核心难点，见第三节）
3. **手机号池轮询**：SQLite 管理，使用次数最少优先；每号跑满 10 题自动登出换号
4. **验证码自动收取**：向 FastAPI 短信服务轮询，只取「点击发送」之后的新码，防拿到历史旧码
5. **后台任务闭环**：从 rpa-service 认领问题 → 心跳续约 → 在 DeepSeek 提问 → 采集回答正文 + 深度思考内容 + 长截图 → 上传截图、回调结果 → 异常自动归还任务池
6. **问答采集**：自动开启深度思考模式、滚动长截图拼接、HTML 化答案（沿用 deepseekapp.py v6 成熟逻辑）

## 二、项目结构

```
deepseek_auto/
├── run.py               # 主入口：CLI + 手机号批次循环 + 后台任务循环
├── config.py            # 全局配置（包名/平台/服务端地址/千问配置/轮询参数）
├── .env                 # 千问 API Key（不提交 git）
├── deepseek_login.py    # 登出①~④ + 登录⑤~⑩ UI 自动化
├── captcha_solver.py    # 【核心】人机验证破解器
├── deepseek_worker.py   # 问答采集（新对话/深度思考/长截图/HTML生成）
├── worker_lib.py        # 后台任务运行时（认领/心跳/归还/回调/上传）
├── phone_db.py          # 手机号池（SQLite）
├── vcode_client.py      # 验证码轮询客户端
├── requirements.txt
├── data\phones.db       # 号池数据（运行时生成）
└── screenshots\         # 任务截图 + captcha_debug\ 验证过程证据
```

### 模块协作关系

```
run.py ──→ phone_db（选号）──→ deepseek_login（登出/登录）
                                │
                                ├→ captcha_solver（破解人机验证）
                                └→ vcode_client（轮询短信验证码）
run.py ──→ worker_lib（认领/心跳/回调）──→ deepseek_worker（问答采集）
```

## 三、核心难点：人机验证破解（captcha_solver.py）

点「发送验证码」后弹出的验证：一张含若干 3D 几何体的大图 + 一句随机问题（如「点击图中最小的黄色圆锥」），点中目标才发短信，点错自动刷新新题。

### 求解管线（三层兜底设计）

**1. 读题**：优先从 UI XML 提取问题文字（最准）；读不到时把整张弹窗图发给大模型让它自己读题作答。

**2. 验证图定位**（三级策略，逐级兜底）：
- 策略 a：XML 里找弹窗内的大 `ImageView` 节点（宽≥屏宽35%、高≥屏高15%，且必须在问题文字上方）
- 策略 b：**OpenCV** 检测——近白掩码+形态学闭运算找出白色圆角弹窗，再在弹窗内找最大非白矩形即验证图
- 策略 c：按历史真实弹窗的相对位置比例裁剪

**3. 目标点识别**：验证图 + 问题发**千问视觉大模型**（qwen-vl 系列，OpenAI 兼容接口，`temperature=0`），要求输出 0~1000 归一化坐标 JSON；解析器兼容三种返回格式（标准 JSON / `(x,y)` 坐标对 / qwen-vl 原生 `<box>` grounding 格式），并做越界丢弃防模型幻觉。

**4. 点击与判定**：坐标映射回全屏 → `d.click()` → 2 秒后重新 dump XML：弹窗消失=通过；仍在则区分「答错刷新」，带着新题进入下一轮，最多 3 轮。

**5. 可观测性**：每轮自动留存证据到 `screenshots\captcha_debug\`——验证图裁剪（`_crop.png`）+ 标注了 AI 点击位置的整屏图（`_marked.png` 绿十字），复盘调优直接用。

### 为什么这套设计稳

- **不赌 resource-id**：DeepSeek 版本更新改 id 不影响，文本/desc 优先 + 坐标兜底
- **不赌固定布局**：横竖屏运行时自适应，OpenCV 按视觉特征找图而非死坐标
- **不赌单次成功**：点错自动接着解新题，3 轮预算覆盖模型偶发失误

## 四、与 doubao_auto 的差异

| 维度 | doubao_auto | deepseek_auto |
|---|---|---|
| 包名 / 平台 | `com.larus.nova` / `doubao_app` | `com.deepseek.chat` / `deepseek_app` |
| 登出路径 | 汉堡菜单 → 齿轮 → 退出登录 | 抽屉 → 三个点 → 设置 → 退出登录 |
| 验证码触发 | 输手机号点「下一步」自动发 | 需点「发送验证码」+ **过人机验证** |
| 人机验证 | 无 | **有，AI 大模型 + OpenCV 破解** |
| 问答采集 | doubao_worker.py | deepseek_worker.py（含深度思考采集） |
| 号池/轮询/回调 | phone_db / vcode_client / 内嵌 worker_lib | 完全复用（worker_lib 抽成独立模块） |

## 五、运行依赖与外部系统

- **雷电模拟器**（adb 连接，DeepSeek App 已安装）
- **FastAPI 短信服务**：提供 `GET /api/sms/vcode?phone=xxx&after=ts` 验证码查询
- **rpa-service**：任务认领 `/internal/rpa/worker/assign`、心跳、归还
- **后台网关**：结果回调 `/api/rpa/callback`、截图上传 `/api/rpa/upload`
- **千问视觉大模型 API**：OpenAI 兼容接口（Key 走 `.env`，支持第三方中转站）

详细启动步骤见 [启动教学.md](启动教学.md)。
