# 豆包 App 自动化问答采集系统 —— 项目开发文档（面试版）

> 本文档用于记录项目从搭建到落地的完整开发过程，涵盖技术选型、系统架构、端口连接、数据流通保障、核心难点及解决方案，可直接作为面试时的项目介绍材料。

---

## 一、项目概述

**项目名称**：豆包 App 自动化问答采集系统（Doubao Auto）

**一句话描述**：基于 Android 自动化框架（uiautomator2）+ FastAPI 短信服务 + 自研任务调度系统，实现豆包 App 的全自动登录（退出登录 → 输入手机号 → 自动发送验证码 → 轮询验证码 → 登录）与问答内容采集（联网搜索资料 + AI 正文 + 长截图拼接），并通过后台任务池完成任务认领、心跳保活、结果回调的完整闭环。

**解决的核心问题**：

1. **多手机号自动轮询登录**：每个手机号连续回答 10 个问题后自动登出换号，避免单账号被风控
2. **验证码自动获取**：通过 Android 短信转发 App + FastAPI 短信服务，把手机收到的验证码自动回传给自动化脚本
3. **长回答完整采集**：通过滚动逐屏截图 + 重叠区域像素比对拼接，得到完整的回答长图
4. **思考过程与正文分离**：把豆包回答中的「联网搜索资料」与「最终回答正文」分别提取，对应回调字段 `thinkingContent` / `answerText`
5. **后台任务调度闭环**：任务认领 → 心跳续约 → 异常归还 → 结果回调，支持多 worker 并发

## 二、技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| Android 自动化 | uiautomator2（Python） | 驱动真机/模拟器，UI 元素定位、点击、输入、滚动、截图 |
| 图像处理 | Pillow + NumPy | 长截图拼接（重叠区域像素差比对）、消息区域裁剪 |
| 任务调度 | 自研 worker_lib（内嵌于 run.py） | 任务认领 / 心跳 / 异常归还 / 结果回调 / 截图上传 |
| 验证码服务 | FastAPI（fastapi_sms）+ PostgreSQL | 接收 Android 短信上报、提供验证码轮询查询 |
| 手机号池 | SQLite（phone_db.py） | 按使用次数最少优先轮询 |
| 短信转发 | Android App（SMSUploader） | 手机收到短信后 POST 到 FastAPI 服务端 |
| 后台任务服务 | RPA Service（8084）+ 回调网关（8080） | 任务池分发、账号池、结果回调入口 |

## 三、项目结构

```
doubao_auto/
├── config.py               # 全局配置：包名、服务端地址、验证码轮询参数、问题列表
├── phone_db.py             # 手机号池（SQLite，使用次数最少优先，支持命令行增删改查）
├── vcode_client.py         # 验证码轮询客户端（GET /api/sms/vcode?phone=&after=）
├── doubao_login.py         # 登录/登出 UI 自动化（基于真实 dump 的 resource-id）
├── doubao_worker.py        # 问答采集：发送问题→等回答→长截图→提取资料/正文
├── run.py                  # 主入口：内嵌 worker_lib + 手机号轮询管理器 + 任务循环
├── requirements.txt
├── data/
│   └── phones.db           # SQLite 手机号池数据库
└── screenshots/            # 每个任务的截图、XML、思考/正文文本输出目录
```

**短信服务端**（独立部署，非本仓库）：FastAPI + PostgreSQL
- `POST /api/sms/receive` — Android 短信转发 App 上报短信入库
- `GET /api/sms/vcode?phone=&after=` — 轮询查询某手机号的最新验证码
- `GET /health` — 健康检查

**短信转发 App**（独立部署）：Android APK，监听手机短信并 POST 到 FastAPI 服务端

### 端口连接说明

| 端口 | 服务 | 方向 | 用途 |
|------|------|------|------|
| **8000** | FastAPI 短信服务 | Worker → 服务端；手机 → 服务端 | Worker GET 轮询验证码；手机 POST 短信入库 |
| **8084** | RPA 后台任务服务 | Worker → 服务端 | 任务认领(`/assign`)、心跳(`/heartbeat`)、异常归还(`/abort`) |

## 五、核心开发步骤

### 步骤 1：环境搭建与设备连接

- 安装 uiautomator2：`pip install uiautomator2`，初始化 atx-agent：`python -m uiautomator2 init`
- 雷电模拟器开启 adb 调试，`adb connect 127.0.0.1:5555`
- `uiautomator2.connect(serial)` 建立设备会话，通过 `d.info` 读取屏幕分辨率

### 步骤 2：登录/登出 UI 自动化（doubao_login.py）

- **dump XML 定位元素**：用 `d.dump_hierarchy()` 导出真实 UI 层级，提取稳定的 `resource-id` 和 `content-desc`
  - 汉堡菜单：`com.larus.nova:id/back_icon`（desc="对话列表"）
  - 齿轮设置：desc="设置页"
  - 新对话：`com.larus.nova:id/larus_chat_top_left_create_new_cvs`
  - 输入框：`com.larus.nova:id/input_text`
- **登出流程**：点汉堡 → 点齿轮 → 滚动设置页 → 点"退出登录" → 弹窗确认
- **登录流程**：勾协议复选框 → 点"手机号登录" → 输入手机号 → 点"下一步"（自动发码）→ 轮询验证码 → 填入 → 确认登录

### 步骤 3：验证码服务对接（vcode_client.py）

- 客户端 `poll_vcode(phone, after_ts)`：每 2 秒 GET 一次 `/api/sms/vcode`
- **关键点**：点"下一步"之前记录 `vcode_send_ts = time.time()`，轮询时传 `after=vcode_send_ts`，服务端只返回 `receive_time > after` 的记录，防止拿到历史旧验证码

### 步骤 4：手机号池（phone_db.py）

- SQLite 表 `phones(id, phone, use_count, last_used, created, note)`
- `pick()`：`ORDER BY use_count ASC, RANDOM() LIMIT 1`，选使用次数最少的号
- `increment(phone)`：使用完 +1，更新 last_used
- 支持命令行：`python phone_db.py add/list/remove/reset/pick`

### 步骤 5：问答采集核心（doubao_worker.py）

- **发送问题**：new_chat → clear_and_input（uiautomator2 set_text，避免 adb input 中文编码问题）→ send_message（多级选择器兜底）
- **等待回答完成**：以豆包的"复制"按钮（`com.larus.nova:id/msg_action_copy`）作为完成标志，连续检测到 2 次才确认；期间若出现"回到底部"按钮则点击保持在底部
- **长截图**：滚到顶部（连续多次画面不变才确认）→ 逐屏截图 → 重叠区域像素比对拼接 → 滚回底部
- **内容提取**：从 XML 中分别提取联网资料（reference 节点）和回答正文（最长 TextView）

### 步骤 6：任务调度与回调（run.py 内嵌 worker_lib）

- `claim_work()`：POST `/internal/rpa/worker/assign` 认领任务
- `heartbeat()`：定期 POST `/internal/rpa/worker/heartbeat` 续约
- `abort_unit()`：异常时 POST `/internal/rpa/worker/abort` 归还任务
- `callback()`：POST `/api/rpa/callback` 回传结果（thinkingContent / answerText / screenshotUrls）
- `upload_screenshot()`：POST `/api/rpa/upload` 上传截图

### 步骤 7：手机号轮询换号（PhoneSessionManager）

- 每完成一个任务 `mark_used()`，批次计数 +1
- `should_relogin()`：当 `_count_in_batch >= 10` 时触发 `force_relogin()`
- `force_relogin()`：logout → force_reset（杀进程）→ start_doubao → pick 新号 → login_with_phone

## 六、核心难点与解决方案（面试重点）

### 难点 1：长截图拼接 —— 顶部/底部判断不准、画面重复或漏截

**现象**：
- 长截图循环无限滚动，到底也停不下来
- 截图内容重复（同一屏被收多次）或漏截（回答中间缺一段）
- 顶部标题栏和底部输入框在每屏都出现，干扰拼接

**根因**：
1. 用整屏截图做签名比对，顶部标题栏和底部输入框固定不变，导致"画面没变"的误判
2. RecyclerView 惯性滚动 + 橡皮筋回弹，截图落在回弹中途，被当成新画面
3. 一次滑动距离太大（半屏），字还没停稳就截图，内容截不全

**解决方案**（`doubao_worker.py` 的 `full_screenshot_mobile` / `scroll_to_top`）：

1. **只截消息滚动区域**（`get_message_list_bounds`）：
   - 优先用 `com.larus.nova:id/message_list_parent` 的 bounds 裁剪
   - 兜底用屏幕比例：顶部裁掉 9%（标题栏），底部裁掉 16% + 6%（输入框 + 悬浮按钮）
   - 这样每屏只有聊天内容，不会被固定 UI 干扰

2. **滚顶确认**（`scroll_to_top`）：
   - 不是调一次 `toBeginning` 就认为到顶，而是循环：截图 → 向上滚 → 再截图 → 比对签名
   - 连续 `stable_rounds=3` 次画面完全不变，才确认到顶
   - 顶部确认后再做一次"最终复核"：再滚一轮，仍无位移才允许第一张截图

3. **短距慢速滚动 + 长等待**：
   - 只在消息区域内滑，从 75% 高度滑到 25%（滑 50% 区域高度）
   - `duration=1.0` 秒慢速滑，惯性极小
   - 滑完 `sleep(2.0)` 秒，确保 RecyclerView 完全停稳

4. **重叠区域拼接**（`find_overlap`）：
   - 把上下两帧缩放到同宽，遍历可能的重叠高度（5%~75%）
   - 对每个重叠高度，取上帧底部和下帧顶部的对应区域，计算平均像素差
   - 像素差最小的重叠高度即为真实重叠位置，裁掉重叠部分拼接

5. **停止条件**：滚动过程中检测到"复制"按钮出现 → 说明回答已完整滚过屏幕 → 停止

### 难点 2：回答完成判定 —— 误判或迟迟不停止

**现象**：
- 回答还没生成完就开始截图（截到半截回答）
- 回答已完成但程序一直等，直到超时

**根因**：
- 早期用"检测不到'停止生成'文字"作为完成标志，但生成中文字在不同 App 版本/状态下不稳定
- 页面停在回答上方时，UI hierarchy 看不到当前回答的操作按钮，导致误判

**解决方案**（`wait_answer_finish`）：

1. **以"复制"按钮作为完成标志**：豆包回答完成后会出现 `com.larus.nova:id/msg_action_copy`（desc="复制"）
2. **连续 2 次检测到才确认**：避免按钮一闪而过的误判
3. **保持在底部**：循环中若出现"回到底部"按钮（`com.larus.nova:id/fast_button`），立即点击，确保页面停在回答底部
4. **超时保护**：最多等 600 秒，超时返回失败

---

### 难点 3：验证码轮询拿到历史旧码

**现象**：
- 点"下一步"发新验证码后，轮询拿到的是上一轮的旧验证码，填入后提示"验证码错误"

**根因**：
- 服务端 `/api/sms/vcode` 只按手机号查最新一条，没区分时间
- 新验证码还没到，旧码还在库里，就被当成最新的返回了

**解决方案**（`vcode_client.py` + `doubao_login.py`）：

1. **记录发码时间戳**：点"下一步"之前 `vcode_send_ts = time.time()`
2. **轮询带 after 参数**：`poll_vcode(phone, after_ts=vcode_send_ts)`，请求 `GET /api/sms/vcode?phone=xxx&after=1700000000`
3. **服务端按时间过滤**：只返回 `receive_time > after` 的记录
4. **超时抛异常**：90 秒内拿不到则抛 `VcodeTimeoutError`，本轮登录失败，下一轮重试

---

### 难点 4：手机号登录流程不稳定

**现象**：
- 登录页找不到输入框、协议复选框没勾上、点"下一步"没反应

**根因**：
- 豆包登录页的 EditText 没有稳定的 resource-id，只能靠 hint 文本匹配
- 复选框在不同版本可能是 CheckBox 或可点击的 ViewGroup
- 发送按钮的 resource-id 在真机和模拟器上不同

**解决方案**（`login_with_phone` / `send_message`）：

1. **多级选择器兜底**：按优先级尝试不同选择器，例如手机号输入框：
   - `textContains="请输入手机号"` → `textContains="请输入11位手机号"` → `className="android.widget.EditText"`
2. **复选框兜底**：先按 CheckBox class 找，再按 `checkable=True` 的 ViewGroup 找，最后按屏幕坐标点击（左下偏左 8%, 87%）
3. **发送按钮兜底**：resource-id（send_button/input_send/send/action_send_container）→ content-desc="发送" → text="发送" → 扫描 XML 中可点击的发送节点 → 最后 Enter 兜底
4. **登录页强制兜底**：如果 4 次返回后仍不在登录页，直接 `app_stop` + 重启 App

### 难点 5：内容提取 —— 联网资料与正文混在一起

**现象**：
- 回调的 `answerText` 里包含了"搜索 N 个关键词、参考 N 篇资料"等资料标题
- `thinkingContent` 为空或不完整

**根因**：
- 豆包的回答正文和联网资料都渲染在同一个消息列表里，XML 中没有明显的结构分隔
- 资料卡片有独立的 resource-id，但正文是普通 TextView，需要从所有 TextView 中筛掉资料相关节点

**解决方案**（`extract_thinking_and_answer`）：

1. **资料提取（thinkingContent）**：
   - 标题：`com.larus.nova:id/tv_reference_title`
   - 搜索关键词：`com.larus.nova:id/sub_keyword_reference`
   - 资料卡片：`com.larus.nova:id/ll_source_item` 下的 `tv_reference_content`
   - 拼装成 HTML（和网页版 doubao.py 格式对齐）

2. **正文提取（answerText）**：
   - 遍历所有 `android.widget.TextView` 节点
   - 排除资料相关的 resource-id（tv_reference_title / tv_reference_content / tv_reference_index / sub_keyword_reference）
   - 排除固定 UI 文字（复制/播放/点赞/点踩/分享/重新生成等）
   - 排除长度 < 10 的短文本
   - 取剩余候选中最长的作为正文

3. **兜底**：如果候选为空，用 `extract_message_blocks` 启发式提取（取长度 ≥ 20 的文本块，去掉父子重复）

4. **HTML 还原**（`_text_to_html`）：手机 App 没有 markdown DOM，用启发式规则把纯文本转成 HTML（空行分段 → `<p>`，`- ` → `<ul>`，`1. ` → `<ol>`，`**加粗**` → `<strong>`，`` `代码` `` → `<code>`），保证前端拿到的格式和网页版一致

### 难点 6：多 worker 并发下的任务状态一致性

**现象**：
- worker 崩溃后任务卡在"执行中"，不会被其他 worker 认领
- 多个 worker 同时认领同一个任务

**根因**：
- 缺少心跳机制，服务端无法判断 worker 是否还活着
- 认领时没有原子性保障

**解决方案**（`run.py` 内嵌 worker_lib）：

1. **心跳续约**：认领任务后启动心跳线程，每 60 秒 POST `/heartbeat`，服务端更新租约时间
2. **异常归还**：`handle_unit` 抛异常时调用 `abort_unit`，任务回到任务池
3. **优雅退出**：`finally` 块中归还正在跑的单元、释放账号、关浏览器
4. **批次换号**：每 10 题释放当前手机号重新借号，避免单账号长时间运行被风控
5. **连续失败熔断**：连续失败 3 次主动退出，避免无效循环

## 七、数据流通保障

### 1. 任务侧闭环

```
claim_work(认领) → heartbeat(心跳续约) → handle_unit(执行) → callback(回调结果)
                     ↓ 异常
                  abort_unit(归还任务池)
```

- 认领时把 `accountId`（手机号）传给后端，回调时知道该用哪个账号更新状态
- 回调携带 `taskResultId` 精确定位对应记录
- 截图先上传到后端拿到 URL，再随回调一起提交

### 2. 验证码侧时序保证

```
点"下一步"(记录 vcode_send_ts) → 短信到手机 → SMSUploader POST 入库
→ Worker GET /api/sms/vcode?after=vcode_send_ts → 只返回本轮新码
```

- `after` 参数是核心：确保只拿发码之后的新验证码，杜绝旧码干扰
- 90 秒超时 + 2 秒轮询间隔，平衡实时性和服务端压力

### 3. 手机号侧负载均衡

- SQLite 记录每个号的 `use_count`，`pick()` 选次数最少的
- 每 10 题强制登出换号，均衡各手机号使用频率
- 异常时也触发 `force_relogin`，确保换号干净

### 4. 截图侧完整性

- 顶部三重确认（连续 3 次无位移 + 最终复核），确保从真正的顶部开始
- 逐屏截图用消息区域签名比对去重，不重复不漏帧
- 重叠区域像素差最小化拼接，保证长图无缝
- 长截图失败时单张兜底，不让任务因截图失败而整体失败

## 八、面试话术要点

### 自我介绍项目时建议这样讲

> "这是一个豆包 App 的全自动化问答采集系统。技术栈是 Python + uiautomator2 做 Android 自动化，Pillow + NumPy 做长截图拼接，FastAPI 做短信验证码服务，SQLite 管手机号池，PostgreSQL 存短信，自研 worker_lib 做任务调度。
>
> 整个流程是：从后台任务池认领问题 → 自动登录豆包（多手机号轮询，每 10 题换号）→ 输入问题发送 → 等回答完成（以'复制'按钮为标志）→ 滚到顶部逐屏截图并拼接成长图 → 提取联网资料和回答正文 → 上传截图并回调结果。
>
> 核心难点有三个：第一是长截图拼接，我只截消息滚动区域排除固定 UI，用连续画面不变确认到顶，短距慢速滚动加 2 秒等待避免惯性，最后用 NumPy 做重叠区域像素差最小化拼接；第二是验证码不拿旧码，点发码前记录时间戳，轮询时带 after 参数，服务端只返回这个时间之后的新验证码；第三是资料和正文分离，通过 resource-id 区分资料节点和正文 TextView，正文取最长的候选，资料单独提取并转成 HTML。"

### 可能被追问的点及回答思路

**Q：为什么用 uiautomator2 而不是 Appium？**
A：uiautomator2 是 Python 原生库，直接基于 Android UIAutomator，不需要起 Appium Server，部署轻量，API 更简洁，适合单机自动化脚本。

**Q：长截图拼接的重叠检测具体怎么做的？**
A：把上下两帧缩放到同宽，遍历重叠高度（从 5% 到 75%），每个高度取上帧底部和下帧顶部的对应区域，resize 到 160×N 后转成 int16 数组，计算平均绝对像素差，差最小的就是真实重叠位置。

**Q：怎么保证不采到上一题的内容？**
A：每个任务开始前都调 `new_chat()` 创建新对话；采集用 resource-id 排除固定 UI 文本；长截图只截当前对话的消息区域。

**Q：登录失败怎么办？**
A：登录抛异常会被 `run_doubao_loop` 捕获，触发 `force_relogin` 重试，连续失败 3 次退出；验证码超时也会抛 `VcodeTimeoutError`，下一轮重新发码。

**Q：怎么保证数据不丢？**
A：任务有心跳续约，worker 崩溃后租约过期任务自动回到池子；截图本地保存一份（screenshots/ 目录），上传失败不影响文本回调；回调失败抛异常触发 abort，任务可被其他 worker 重试。

## 九、启动与自检

```bash
# 安装依赖
pip install -r requirements.txt

# 添加手机号
python run.py --add 13800138000

# 列出手机号池
python run.py --list

# 自检（FastAPI / 手机号 / adb / RPA 服务）
python run.py --check

# 本地测试 1 轮（不连任务池）
python run.py --once

# 正式运行（连任务池，自动认领任务）
python run.py
```

1. FastAPI 短信服务健康检查（`/health`）
2. 手机号池非空
3. adb 设备已连接
4. RPA 后台服务可达（`/actuator/health`）
